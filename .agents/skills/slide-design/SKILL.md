# スライドのデザインバランス（白地 olivia）

このデッキの既定は `suraido.js/themes/olivia.css`（クリーム地にサーモン）。投影すると白地より粗が目立つのは同じで、余白の不揃い、沈んだ色、下端に張り付いた図は、当日に分かる。

> 出典: [minorun-marp-skill](https://github.com/minorun365/minorun-marp-skill)（Apache-2.0）を suraido.js 向けに改変。

数値の正本はテーマと `tools/measure-deck.mjs` にある。この文書は「なぜその数字か」と「どこを見るか」を持つ。

- テーマ: `src/index.tsx` の `import "suraido.js/themes/olivia.css"`
- 測る: `npm run measure`（開発サーバーを立てた状態で）
- 機構の約束（`class`、`deck()`、`<Step>`、はみ出し）は `AGENTS.md` が正本

## 文字の大きさ

数字はテーマのトークンと `src/slides.css` に置く。`measure` は 30px 未満を落とす（等幅の `code` だけ 28px を許す）。

| 場所 | サイズ | 出どころ |
|---|---|---|
| 表紙の見出し（`h1`） | **96px** | `--suraido-h1` |
| 本文の見出し（`h2`） | **64px** | `--suraido-h2` |
| 中扉（`.crosshead h2`） | **72px** | `src/slides.css` |
| 小見出し（`h3`） | **40px** | `--suraido-h3` |
| 本文・箇条書き | **32px** | `--suraido-text` |
| 表の見出し行（`th`） | **30px** | `src/slides.css` |
| 表のセル（`td`） | **32px** | `src/slides.css` |
| コード（`pre`） | **28px** | 例外。等幅なのでこの1つだけ下げる |
| 図の中のラベル | **30〜36px** | `src/slides.css` |
| 数字を主役にする `b` | **200px** | デッキで1〜2枚まで |

- 見出しは64pxで、1920pxの版面に全角26字まで入る。入らない見出しは短くする
- 迷ったら下げずに、文言を削る。1枚だけ小さいと通しで不揃いとして出る
- テーマを変えたら、まずこの表の値が実際に出ているかを測る

## 余白は測ってから決める

「もう少し上へ」「余白をあけて」と言われて、値を勘で足し引きしない。根拠の無い数字で触ると、直したつもりの箇所が別の要素とぶつかり、同じ指摘を何巡も受ける。

```bash
npm run dev &
npm run measure -- --verbose     # 全スライドの下端・右端の空きと NG の位置
```

座標は 1920x1080 のキャンバス上の px で、ブラウザの開発者ツールで読める数字とそのまま同じ。

- 下限は **そのスライドの padding**。`--suraido-pad: 96px 120px` なので、中身は下 96px・右 120px の内側で終わる。`measure` は padding を読んで判定するので、テーマを変えれば下限も変わる
- 要素どうしは 72px 以上あける（`--suraido-gap`。`<Cols>` の列間にも同じ値が入る）
- 横位置は、スライドの中央か、本文の左端（120px）に揃える。本文の余白より外へ出さない
- 縦位置は、本文の下端からスライド下端までの空きの縦中央に置く。本文の長さが違うスライドごとに値を持ち替える

左右の余白が 120 対 121、上下が 96 対 99 のように両側の差が数pxなら、バランスは取れている。ずれていたら、その数字がそのまま直す量になる。

素材を差し替えただけで見せない。図や写真を入れ替えたら、同じ作業のなかで幅、四方の余白、見出しとの間隔、隣の要素との重なりまで整える。入れ替えは作業の半分で、残りの半分がレイアウトの調整である。

## 書体

和文は **Noto Sans JP** を第一候補にする。`src/slides.css` の `--suraido-font` で固定してあり、Windows では可変フォント（weight 100–900）がそのまま出る。macOS は Hiragino Sans、それも無ければ Yu Gothic UI → system-ui へ落ちる。

```css
--suraido-font: "Noto Sans JP", "Hiragino Sans", "Yu Gothic UI", "Yu Gothic", "Meiryo", system-ui, sans-serif;
--suraido-font-mono: ui-monospace, "Cascadia Mono", "SF Mono", Menlo, Consolas, monospace;
```

- フォントを言葉で相談しない。同じページを候補ごとに書き出して並べる（色と同じ）。比べるのは見出し1行・本文1行・数字が並んだ行の3つ
- 会場の PC で読めているかを先に確かめる。`document.fonts.check('32px "Noto Sans JP"')` が false でも崩れない（スタックの最後まで書いてある）。読めていないのに気づかないまま投影するのが一番まずい
- 丸ゴシック（Zen Maru Gothic）を使いたいなら、woff2 を同梱して `@font-face` で読む。会場のネットワークを前提にしない
- 和文は欧文より字面が大きい。サイズを揃えても和文だけ大きく見えるので、字間でごまかさない。サイズか行間で直す
- 見出しの `letter-spacing: -0.02em` は欧文向け。和文の見出しが詰まって見えたら 0 に戻す（`h2 { letter-spacing: 0 }`）
- 数字と英字は同じフォントでよい。混植すると行の高さが揃わない

## 縦のバランス
- 本文は見出しの直下から始める。本文が短くて下が空いても、それが普通の形である。見出しと本文のあいだを広げて中央に見せる組み方はしない
- 空きを作るなら、段落のあいだの改行か、右下の挿絵や箱で埋める
- 図が主役のスライドだけは、図を見出しの直下に貼らない。図の上に 36px 前後、図の下の本文にも 44px 前後を取り、図と本文で版面を上下に分ける
- 本文の下に画像や表が来て、その下に何も無いスライドは、画像の上の空きと下の空きを等しくする。上下を実測し、差が 6px を超えたら `position: relative; top: <差の半分>px` で下げる
- `<Pad>` は `height: 100%` の素の `section` で、中身は上から積まれる。縦中央に寄せたいときは `<Pad>` ではなく `<Center>` を使う。`margin: auto 0` では寄らない
- 表を中央へ寄せるなら `display: table; width: auto; margin: <上の空き> auto 0`
- 本文の段落は3行まで。3行目に括弧の補足を足すと窮屈になる
- 収まらないときにフォントサイズを下げない。①意味の切れ目で改行 ②前後の枚へ分割 ③内容を削る、の順。1スライドだけ文字が小さいと、通しで見たときに不揃いとして出る
- 横に並べた画像は、高さではなく幅で頭打ちになる。大きくしたいなら、まず画像の数を減らせないかを考える
- 見出しと似た表現の箱を、見出しの直下に置かない。同じことを2回言っているように見える。箱はスライドの最下部へ回す
- 1語だけが次の行に落ちる折り返しは、全部つぶす。読点や句点の位置で自分で改行する。JSX では `{"\n"}` ではなく `<br />`

デザインの直し方を発明しない。バランスが悪いと言われたら、まず同じ構成のスライドを過去のデッキから探して真似る。新しいCSSの型を作るのは最後の手段で、作るなら先に1スライドだけ試して見せる。

## 配色

感覚で色を選び直さない。地との明度比、トーン、面積の3つの物差しで決める。

### olivia のトークンと、いまの比

```css
:root {
  --suraido-bg: #f3eee8;      /* クリーム */
  --suraido-fg: #2f2c2a;      /* 12.0 : 1 */
  --suraido-accent: #b35a45;  /*  4.1 : 1 */
  --suraido-accent-2: #8c8279;/*  3.3 : 1 */
  --suraido-muted: #736a62;   /*  4.6 : 1 */
  --suraido-rule: color-mix(in oklab, var(--suraido-fg) 18%, transparent);
}
```

比は「地 `#f3eee8` との明度比」。ここから分かること。

- 本文は `--suraido-fg`（12:1）。迷ったらこれ
- `--suraido-accent` は 4.1:1。**大きい文字と面にだけ使う**。32px 以上の見出し・強調は 3:1 で足りるが、小さい文字には足りない。白文字を乗せる面（4.7:1）なら本文サイズでも読める
- `--suraido-muted` は 4.6:1。補足の1行まで。長い本文には使わない
- `--suraido-accent-2` は 3.3:1。罫線・アイコンの線・薄い面まで。文字には使わない

明度比を測り直すときは、テーマの色を変えたあとに `npm run measure` が実際の描画色で判定する（グラデーションの上は測れないので、目で見る）。

### 面の明るさの上限は、上に乗る白文字が決める

面を濃くするほど地から浮き、白文字が読めるようになる。逆に淡い面に白文字を乗せると消える。淡い面に文字を置くなら、文字は `--suraido-fg` にする。

### 同じ色でも、面は明るく、線は暗く見える

同じ色を、大きな塗りの面と細い文字の両方に使うと、面は明るく、文字は沈んで見える。「表紙の色はいいのに本文の色が濃い」と言われたら、まずこれを疑う。文字と細い線に使う色を、面の色より1〜2段濃くする。

### 2色が喧嘩する原因は、色相よりトーン

色相環の距離だけで判断しない。明度と彩度が揃っていないほうが、原因として多い。片方が白を含む淡い色で、もう片方が原色だと、色相が近くてもぶつかる。

直す順番は、まず明度と彩度を相手に寄せる、それでも駄目なら色相を離す、である。色相を動かすと色の意味まで変わる（黄色の強調を緑にすると「成功」に読める）ので、最後の手段にする。

### メリハリは色を足さず、主役以外を落とす

表や図がのっぺりして見えるなら、全部が `--suraido-fg`（12:1）になっている。主役の色は動かさず、罫線、ラベル、注記のほうを落として段差を作る。段差は倍々が目安（12 → 6 → 3）。1.5倍以内では変えた気がしない。罫線は色と一緒に太さも落とす。

### 製品を紹介するデッキは、その製品のブランド色を使う

公式サイトのCSSやドキュメントの設定から色コードを取る。ブランド色をそのまま文字に使うと地に沈むので、用途で明度を変える。

- 文字に使う色は明度を下げる（見出し、強調、注記の順に濃く）
- 図形の地は逆に淡くして、文字を濃く抜く
- 表紙の帯だけは、ブランド色そのままでよい

### 候補は実物のページに当てて見せる

色見本や数字だけでは決まらない。同じページを候補の数だけ書き出して、2×2のグリッドに並べる。本文の強調が乗るスライドと、図の中で使われるスライドの2つで比べる。1つだけだと、図の中の他の色との相性を見落とす。

suraido なら、`src/slides.css` の `:root` で `--suraido-accent` を差し替えながら同じページを撮ればよい。ブラウザの開発者ツールで変数を書き換えれば、その場で全ページに当たる。

フォントも同じで、言葉で相談せず書き出して見せる。候補ごとに表紙・箇条書き・表の3ページを書き出して並べる。

### 色の一括置換

「気にしない色」を除外条件にした検索を使わない。同じ行に対象の色と除外する色が両方あると、行ごと消えて見落とす。置き換える色そのもので探し、置換後に旧色が0件になることを確かめる。

```bash
rg -n -i '#b35a45|#8c8279|#736a62' src theme
```

## 強調

- 1スライドに1か所まで。デッキ全体では、本文2〜3スライドに1か所。残すのは各パートのパンチライン（柱の名前、締めの一言、鍵になる数字）だけで、説明文の中の便利な語句には付けない
- 表の1列をまとめて塗る用法は、列として揃っていれば1か所と数える
- 数字を3つ並べるスライドは、次のスライドへつながる1つだけを塗る
- 表のセルの中で `<strong>` を使わない。セルは本文より小さく、強調が沈む

## 確定デザイン

どれも、何度か作り直して落ち着いた形である。`src/slides.css` に置く。

### 表は地を塗らず、罫だけ

テーマ既定の表は地が付く。通ったのは、地を塗らず細い罫だけの形。

```css
table { display: table; width: 100%; border-collapse: collapse; background: transparent; font-size: 32px; }
table thead, table tbody, table tr { background: transparent; border: none; }
table th { background: transparent; color: #736a62; font-weight: 600; font-size: 30px; letter-spacing: .06em;
  text-align: left; padding: 0 .7em .55em; border: none; border-bottom: 1px solid #ddd3c9; }
table td { background: transparent; color: #2f2c2a; padding: .5em .7em; line-height: 1.4;
  border: none; border-bottom: 1px solid #ebe2d9; vertical-align: top; }
table tr:last-child td { border-bottom: none; }
table td:first-child { font-weight: 700; white-space: nowrap; }
```

- `td` だけを透明にすると、テーマ既定の `tr` の背景が透ける。`table / thead / tbody / tr` にも必ず当てる
- 表は JSX で `<table><thead><tr><th>…` と書く
- セルは1行に収める。`white-space: nowrap` を当てて、はみ出したら文言を削る。自動の折り返しに任せると、最後の1文字だけが2行目に落ちる
- 列に色の階層をつける。1列目は `--suraido-fg` の太字、説明の列は `--suraido-muted`、主役の列は `--suraido-accent` の太字
- 注目させる行はアクセントの薄い網掛け（`rgb(179 90 69 / 12%)`）。6行以上の比較表では必須
- 6行を超える表は下端に届く。行を減らすか、`td` の padding を詰める
- 表の下に、灰色の小さい注記を置かない

### コードは淡いパネルに、文字はモノトーン

```css
.win { position: relative; border-radius: 16px; margin: 12px 0 32px; padding: 24px 0 6px; overflow: hidden;
  background: #efe8e0; border: 1px solid #e3d8cc; box-shadow: 0 12px 28px rgb(47 44 42 / 8%); }
.win::before { content: ""; position: absolute; left: 0; right: 0; top: 0; height: 4px;
  background: linear-gradient(90deg, #b35a45 0%, #d99a86 45%, rgb(217 154 134 / 0%) 100%); }
.win pre { background: transparent; box-shadow: none; border: none; margin: 0; padding: 0 32px 18px;
  font-size: 28px; line-height: 1.4; }
```

- コードは 28px を下限にする（本文 32px より少し小さいが、等幅なので読める）。1行は半角60文字まで
- サンプルは1つに絞り、1行に1プロパティで書く。複数のプロパティを1行に畳むと読めない
- 構文の色は2色までに絞る。関数名・変数まで塗り分けると色が散る
- 箱の下端は、ページの下端（padding 96px）から内側へ収める

### 補足ボックス

本文の下の空きへ、角丸のボックスを置き、補足の1行を入れる型。

```css
.gbox { position: absolute; left: 0; right: 0; margin: 0 auto;
        width: fit-content; min-width: 900px; max-width: 1080px;
        bottom: 128px; background: #ebe2d9;
        border: 1px solid #ddd0c2; border-radius: 16px; padding: 18px 64px; text-align: center; }
.gbox, .gbox p { font-size: 30px; line-height: 1.4; }
.gbox p { margin: 0; }
.gbox.up { bottom: 200px; }        /* 本文が短く、下の空きが広いスライド */
```

- `left:50%` と `translateX(-50%)` で中央に寄せない。使える幅が画面の右半分だけになり、収まるはずの文が折り返す
- `min-width` で、複数のスライドのボックス幅を揃える。いちばん長いスライドの自然な幅を測って下限にする
- `position: absolute` の基準は `section`。`src/slides.css` の `.suraido-pad { position: relative }` がそれ
- 中に段落が1つしか無いなら `<p>` を書かなくてよい。div 直下の文字にも当たるよう、`.gbox` と `.gbox p` の両方に `font-size` を書く

### 結論と引用の箱

結論は `--suraido-accent` のベタ塗りに白の太字、引用は左端のアクセントの縦線。淡い地に濃い文字の箱を並べると、どれが結論か分からなくなる。

```css
.callout { width: 88%; margin: 0 auto; border-radius: 16px; padding: 24px 44px;
           background: var(--suraido-accent); color: #ffffff; font-weight: 700; text-align: center; }
.quote { position: relative; border-radius: 4px 12px 12px 4px; padding: 20px 40px;
         background: #efe8e0; }
.quote::before { content: ""; position: absolute; left: 0; top: 0; bottom: 0; width: 4px;
                 background: var(--suraido-accent); }
```

箱の形は好みが割れやすい。同じスライドに2〜3案を当てて並べ、選んでもらう。

- 箱は `width: fit-content; max-width: 100%`。幅いっぱいの箱に短い行を並べると、右側だけ空いて左に寄って見える
- 改行は読点の位置で、箱の幅いっぱいまで使って入れる。1行10字台の行を5行積まない
- 段落が2つあるときは `<p>` を2つ書いて `p + p { margin-top: 18px; }`。`<br />` だけで続けない

### 図のラベルは箱の外の上に置く

箱の中には中身だけを入れる。箱が何であるかの名前は、箱の上 14px に小さく置く。

### スクリーンショット

`<Cols ratio="3fr 2fr">` の右へ置くと右端に密着する。中央に置くなら `<Pad>` の中で `<img class="shot">`（`margin: 0 auto; width: 720px; border-radius: 12px`）。2枚を左右に並べるときは、縦横比を揃える。片方だけ縦長だと、説明の開始位置が左右でずれる。

### 見せ方のリズム

- 文章のスライドが5つ続くと単調になる。引用だけのスライド、2カラム、挿絵、スクリーンショットの中央置きを混ぜる
- 同じ型の図のスライドが6つ続くのも同じ。図のスライドと、文章と挿絵のスライドを交互にする

## 検査する

suraido は、版面からコンテンツがあふれてもエラーを出さない。書き終えたら毎回、数字と目で見る。

```bash
npm run dev &
npm run measure                                            # 切り取り・余白・文字・明度比・間隔・画像
node tools/check-svg-box-fit.mjs src/images/*.svg --width 820
node tools/check-svg-contrast.mjs src/images/*.svg --bg '#f3eee8'
```

`measure` の下限は、下端・右端がそのスライドの padding、要素の間隔 72px、文字 30px、本文の明度比 4.5:1（48px 以上は 3:1）。黒地の下端は、テキストの位置ではなく、画像・図・コードの箱も含めた最後の要素の位置で測る（ツールは両方を見ている）。

NGは全件を列挙してから要約する。先に要約すると、3件目を見落とす。

### 機械検査のあとに、自分の目で見る

検査が全部OKでも、目視は省けない。検査は存在する要素を測る仕組みなので、要素が丸ごと描かれなかった崩れは1つも検出できない。検査OKの報告と、目視の報告は分けて書く。

```bash
node node_modules/@suraido/cli/dist/cli.mjs export dist --png --out /tmp/all   # 全ページをPNGに焼いて並べる（任意）
```

目視でしか捕まらないものは、文字と挿絵や図形の重なり、下方向の余白のつぶれ、矢印の軸が隠れて矢尻しか見えない状態、見出しの大きさや位置のページ間の不揃い、不自然な改行、挿絵の入れ忘れ、挿絵とキャプションの密着、リード文と図形の間隔の詰まり、本文が左へ寄って右が空く配置である。
