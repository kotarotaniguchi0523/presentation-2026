# 黒地にするときの差分

このデッキの既定は白地（`olivia`）。ここは `theme/minorun-dark.css` に切り替えたときだけ効く話で、余白の測り方・縦のバランス・強調の上限・検査の回し方は `slide-design` と同じ。

> 出典: [minorun-marp-skill](https://github.com/minorun365/minorun-marp-skill)（Apache-2.0）を suraido.js 向けに改変。

```tsx
import "suraido.js/deck.css";
import "../theme/minorun-dark.css";   // olivia の行と入れ替える
import "./slides.css";
```

## 黒との明度比

```python
def lin(c):
    c /= 255
    return c/12.92 if c <= 0.03928 else ((c+0.055)/1.055)**2.4
def L(h):
    h = h.lstrip('#'); r,g,b = (int(h[i:i+2],16) for i in (0,2,4))
    return 0.2126*lin(r) + 0.7152*lin(g) + 0.0722*lin(b)
def vs_black(h): return (L(h)+0.05)/0.05      # 黒背景との比
def vs_white(h): return 1.05/(L(h)+0.05)      # 上に乗せる白文字との比
```

| 用途 | 黒との明度比の目安 |
|---|---|
| 見出し、線、枠（黒の上の文字と細い線） | 10〜12 |
| ベタ塗りの面（上に白文字を乗せる） | 6〜7 |
| 図の主役の箱の地（白文字あり） | 4.5〜5.5 |
| 本文に置く補足ボックスの地 | 2.5〜3.0 |
| 図の中の脇役の箱の地 | 1.5前後 |

シアン `#00c4e4` は 10.0、純黄 `#ffff00` は 19.6。見出しの色が 10 を切ると、濃く沈んで見える。

本文に置いて読ませる補足ボックスを、脇役の箱と同じ 1.5 で作らない。背景と同化する。作者の例では `#2f2f37`（1.58）が沈み、`#555561`（2.86）で枠が立った。上限を決めるのは枠の中に置く強調色で、黄色の強調を載せるなら、地と黄色の比が 6 を切らないところで止める。

面を明るくするほど白文字が読めなくなる。白の大きな太字（50px前後）を乗せるなら白との比 3.0 が下限、図の中の小さめの文字（32px）なら 4.0 以上。白文字のまま面をもっと明るく、という要望は両立しないので、上限にあることを数字で示してから文字色を変える案を出す。

## 暗い地で作り直すもの

白地のデッキから黒地版を派生させるとき、図の色だけを機械置換して済ませない。白地向けの濃い青のグラデーションの図形や、明るい色のベタ塗りの箱は、黒地では浮く。図形は暗いグレーの面（上から下へ `#2c2c35`→`#18181e`、枠 `#3c3c46`）に白文字にし、主役の1つだけを濃いティール（`#00788c`）のベタ塗りに白抜きで立てる。

### 表は罫だけ（黒地用の罫色）

```css
table th { color: #a09aa4; border-bottom: 1px solid #3a3640; }
table td { color: #e9e6ec; border-bottom: 1px solid #221f28; }
table td:first-child { color: #ffffff; }
```

白地の `#ddd3c9` / `#ebe2d9` をそのまま使うと、黒地では線が明るすぎて表が浮く。罫は「地より2段明るい」くらいに落とす。

### コードは半透明のパネル

```css
.win { background: linear-gradient(165deg, rgba(255,255,255,.10) 0%, rgba(255,255,255,.045) 100%);
  border: 1px solid rgba(255,255,255,.14); box-shadow: 0 18px 44px rgba(0,0,0,.45); }
.win pre code { color: #f2f1f5; }
```

白地の `#efe8e0` のパネルは、黒地では明るい四角として浮く。半透明の白を重ねた面にして、地の黒を透かす。

### 結論と補足の箱

結論や引用の箱を、明るい色のベタ塗りに濃い色の文字で作らない。黒地では浮いて見える。薄い網掛けも沈んで読めない。半透明の白を重ねたガラス調の面も、黒地に溶けて、本文と本文のあいだに仕切り線があるだけに見える。

- 結論は補足ボックスと同じ濃い灰色（`#555561`）のベタ塗りに白の太字
- 引用は左端のテーマ色の縦線。地は `rgba(255,255,255,.075)` → `rgba(255,255,255,.02)` の淡いグラデーション
- 補足ボックスの地は `#555561`、`min-width` で複数枚の幅を揃える（型は `slide-design` と同じ）

## 白地の図を持ち込まない

黒地の図は、白地の図の色を替えて作ることが多い。すると、白地の側に後から入った直し（配置の変更、サブラベルの撤去、窮屈さの解消）が黒地版へ届かない。

- 作る前と登壇前に、白地版と黒地版の図を、文字と rect の座標で1組ずつ比べる。色は違って当然なので比べない。違いが出たら、どちらが新しい直しかを履歴で確かめて新しいほうへ寄せる
- 色替えのとき、下の面と同じ色を上の図形に当てていないかを測る

```bash
node tools/check-svg-contrast.mjs src/images/*.svg --bg '#000000'
node tools/check-svg-box-fit.mjs src/images/*.svg --width 820
```

- `--png <dir>` で黒地の上に大きく描き出し、1点ずつ目で見る。スライドに縮めた状態では、吹き出しの潰れも枠からのはみ出しも見えない
- 白地のテーマから派生したデッキは、ページごとの `<style>` に残った白地用の文字色も消す。濃い紺やグレーの文字色は、黒地ではほぼ読めない。白地の色コードを `rg -n -i` で引いて0件にする

## 測る

`npm run measure` は地の色を読んで明度比を出すので、黒地に切り替えてもそのまま使える。下端・右端の下限は padding（黒地テーマも 96/120）で、白地と同じ。

```bash
npm run dev &
npm run measure -- --verbose
```

`suraido.js` の機構の罠（`class`、`deck()`、`<Step>`、はみ出し）は `AGENTS.md` が正本。ここには書かない。
